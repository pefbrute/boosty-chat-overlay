## 1. Текущая архитектура `boosty-chat-overlay` (версия 0.4.0)

Проект представляет собой работающий автономный локальный стек для стримеров, не требующий внешних серверов, облачных баз данных или передачи пользовательских токенов третьим лицам:

```text
[ Boosty Live Chat (Браузер стримера) ]
                 │
                 ▼  MutationObserver + DOM Parser
[ Browser Extension (Boosty Chat Connector) ]
                 │
                 ▼  HTTP POST /message + Heartbeat
[ Local Node.js Server (127.0.0.1:17369) ]
                 │  - Ring buffer (50 сообщений)
                 │  - Deduplication (5s window + FNV-1a hash)
                 │  - Last-Event-ID reconnection
                 ▼  Server-Sent Events (SSE /events)
[ Transparent HTML/CSS Overlay ] <──────────┐
                 │                          │ OBS Browser Source
                 ▼                          │ auto-injected
[ OBS Studio via OBS WebSocket v5 ] ────────┘
```

### Ценные компоненты, которые уже реализованы и работают стабильно:

1. **Boosty DOM Parser (`extension/parser.js`):**
   - Полностью изолированный модуль (Node.js + Browser), не имеющий сторонних зависимостей.
   - Покрыт юнит-тестами с фикстурами.
   - Извлекает автора, текст, аватары (теги `<img>` и CSS `background-image`), ссылки, цитаты/ответы.
   - **Детерминированный fallback ID**: вычисление FNV-1a хеша (`pathname|author|text|publishTime`) при отсутствии нативного `data-id` от Boosty.
   - **Rate-limited диагностика**: логирование аномалий не чаще 1 раза в 5 секунд без утечки персональных данных.

2. **Неинвазивная доставка Extension → Localhost:**
   - Не требует логина и пароля от Boosty внутри приложения, не крадет cookies и не имитирует пользователя через скрытые API.
   - Heartbeat и телеметрия вкладки (`/connector`, `/health`) для контроля соединения в GUI.

3. **Локальный сервер устойчивости (`server.js`):**
   - Нулевые внешние рантайм-зависимости для сервера (чистый `node:http`).
   - Буфер истории (50 сообщений) с серверным таймстампом `receivedAt`.
   - Поддержка стандарта SSE (`text/event-stream`) с заголовком `Last-Event-ID` для бесшовного восстановления оверлея при переключении сцен или перезапуске OBS.
   - Подавление дубликатов по ID.

4. **Оверлей и предпросмотр (`overlay/`):**
   - Полноценная система позиционирования (привязка к 4 углам, направление потока сообщений `top`/`bottom`, смещения `offsetX`/`offsetY`, ограничение высоты `maxStackHeight`).
   - WYSIWYG Live Preview в окне настроек (пропорциональное масштабирование 1080p через CSS transform).
   - Защита от утечек памяти (кольцевой кэш `seenMessageIds` на 300 элементов).
   - Безопасный рендеринг через `textContent` (защита от XSS из чата).

5. **Глубокая интеграция с OBS WebSocket (`desktop/main.js`):**
   - Использование официального протокола OBS WebSocket v5 (`obs-websocket-js`).
   - Автоматическое создание изолированной служебной сцены `Boosty Chat Overlay` и источника `Boosty Chat` с встраиванием в выбранную пользователем сцену (чистая изоляция без мусора в чужих сценах).
   - Восстановление при удалении и безопасная смена сцены.

6. **Тестовая инфраструктура:**
   - Серверные тесты, тесты парсера на синтетических фикстурах, интеграционные тесты с реальным headless Electron (`test:integration`).

## 3. Глубокий разбор AxelChat (`3dproger/AxelChat`)

### 3.1. Юридический статус и лицензия: **ШОКИРУЮЩИЙ ФАКТ**
- Репозиторий `3dproger/AxelChat` **НЕ ЯВЛЯЕТСЯ OPEN-SOURCE ПРОЕКТОМ** приложения!
- В репозитории **полностью отсутствует исходный код десктопного приложения**. В репозитории хранятся только markdown-документы (`README.md`, `docs.md`, `eula.md`, `privacy.md`), скриншоты, иконки и бинарные релизы (`AxelChat_v0.48.1-beta-win64.zip` объемом 245 МБ).
- В файле `eula.md` явно закреплено:
  > *"The Software and all worldwide copyrights, trade secrets, and other intellectual property rights therein are the exclusive property of Developer... You may not sell, resell, rent, lease or exchange the Software... you may not repackage or bundle the Software with any other software unless permission has been given by the developer."*
- **Вывод по форку:** Сделать форк AxelChat **юридически и технически невозможно** — исходного кода приложения в открытом доступе нет, а EULA прямо запрещает перепаковку и модификацию.

### 3.2. Что открыто: репозиторий виджетов `AxelChatWidgets`
Открыт только субмодуль `AxelChatWidgets` (`https://github.com/3dproger/AxelChatWidgets`), распространяемый под лицензией **GPL-3.0**.
- Это чисто клиентский фронтенд на **React + TypeScript + Vite/CRA**, который подключается к локальному закрытому ядру AxelChat по WebSocket (`ws://127.0.0.1:8356`).
- В файле `src/ProtocolInterfaces.tsx` содержится хорошо структурированная модель сообщений (`Message`, `MessageUser`, `MessageContent`, `Segment`).

### 3.3. Как в AxelChat реализован Boosty
Из примечаний к релизам (`releases`) и документации AxelChat (`docs.md`):
- `0.48.1-beta`: *"Boosty: Recurring subscription payments (renewals) are now displayed"*
- `0.41.2`: *"Boosty: Authorization has been fixed in some cases"*
- `0.41.1`: *"Boosty: Now you can connect even if the broadcast has not been created. Notifications about subscriptions, donations, and other events will still arrive"*
- `0.41.0`: *"Added integration with Boosty"*

**Ключевые технические выводы о реализации Boosty в AxelChat:**
1. AxelChat требует **прямой авторизации аккаунта** стримера (ввод учетных данных / cookies внутри приложения или встроенного веб-окна).
2. Он работает с внутренними закрытыми REST/WebSocket эндпоинтами Boosty, нацелен на события донатов, платных подписок и продлений.
3. **Сравнение со стабильностью нашего решения:**
   - **Способ AxelChat (авторизация + закрытый API):** уязвим к блокировкам сессий, требует от пользователя доверять стороннему закрытому приложению свой пароль/сессию от Boosty. При смене схемы авторизации Boosty коннектор ломается полностью (что видно по чейнджлогам «Authorization has been fixed»).
   - **Наш способ (DOM Parser + Extension в личном браузере):** стример авторизован в своем штатном защищенном браузере (Brave, Chrome). Расширение пассивно читает только открытый чат трансляции через `MutationObserver`. Никакие пароли, токены или платежные сессии не покидают браузер.
   - **Вердикт:** Наш подход **безопаснее для стримера** и не зависит от механизма OAuth/сессий Boosty.

### 3.4. Архитектура API AxelChat (что можно позаимствовать)
Хотя приложение закрыто, документация его локального HTTP/WS API (`docs.md`) полезна как референс:
- Эндпоинт `POST /api/v1/receive-events` принимает внешние события в JSON формате (актуально, если мы захотим сделать наш `boosty-chat-overlay` совместимым источником для внешних систем).
- Модель сообщений `AxelChatWidgets/ProtocolInterfaces.tsx` (разделение на сегменты: `text`, `image`, `hyperlink`, флаги бейджей) — отличный ориентир для типизации TypeScript.

## 5. Разбор остальных кандидатов

### 5.1. ChallaChat (`challacade/challachat`) — *Идеальный архитектурный референс*

- **Лицензия:** **Apache License 2.0** (полностью разрешает форк, модификацию, коммерческое использование, с обязательным сохранением копирайтов).
- **Стек:** Electron, TypeScript, Express, SSE, Puppeteer-core.
- **Активность:** Очень активен (коммиты за октябрь 2026, версия 0.9.94).
- **Архитектура:**
  - `app/capture/`: адаптеры платформ (`base.ts`, `youtube.ts`, `twitch.ts`, `kick.ts`). Каждый адаптер изолирован и нормализует поток в общий тип `ChatEvent`.
  - `app/core/sseHub.ts`: легковесный концентратор SSE-соединений (архитектурно идентичен нашему `server.js`).
  - `admin/`: локальная панель управления стримера (настройки стилей, цветов, фильтрация).
  - `overlay/`: HTML/CSS оверлей для OBS.
- **Механизм захвата:** ChallaChat запускает локальный headless Chrome через `puppeteer-core`, подменяет User-Agent и внедряет скрипты перехвата прямо в headless страницу стрима.
  - *Плюс:* Стримеру не нужно ставить расширение в свой браузер.
  - *Минус:* Высокое потребление ОЗУ (headless Chrome тратит 150–300 МБ памяти на каждый чат) и высокий риск сломаться на Cloudflare/капче при открытии страниц авторизации.
- **Пригодность для форка:** **Высокая (4.5/5)**. Проект чистый, написан на TypeScript, использует ту же SSE-модель оверлея, что и наш проект.

### 5.2. StreamHelper (`Rayness/StreamHelper`) — *Лучший референс для современного GUI*

- **Лицензия:** **MIT** (максимально либеральная лицензия).
- **Стек:** Electron, `electron-vite`, React 19, TypeScript, Vitest, `obs-websocket-js` v5.0.8.
- **Активность:** Свежий проект (сентябрь 2026).
- **Архитектура:**
  - `src/main/obs/obs.ts`: образцовая реализация сервиса OBS WebSocket на базе библиотеки `obs-websocket-js` v5 (авто-реконнект, реактивные состояния сцен, подписка на события OBS, синхронизация мутов и источников).
  - `src/renderer/`: современный одностраничный интерфейс на **React 19** с поддержкой русского и английского языков (`i18n.ts`), темной темой, красивыми переключателями и превью.
  - `src/main/overlay/`: локальный HTTP/WS сервер оверлеев.
- **Пригодность для форка:** **Средняя для прямого форка, но Высокая (5/5) как донор UI/React архитектуры**. В проекте много специфичных модулей (донатные алерты, чат-бот, интеграции с Windows Media Control WinRT), которые для минималистичного Boosty-оверлея избыточны.

### 5.3. Social Stream Ninja (`steveseguin/social_stream`) — *Функциональный гигант, но архитектурный монолит*

- **Лицензия:** **GPL-3.0** (строгий копилефт: любой производный код обязан открываться под GPL-3.0).
- **Стек:** Монолитный репозиторий: Browser Extension + HTML/CSS/Vanilla JS (4168 файлов, более 400 МБ).
- **Поддержка платформ:** 90+ платформ, включая трансляцию чатов через P2P WebRTC, YouTube, Twitch, TikTok, Trovo, VK.
- **Архитектура:** Отсутствует модульное разделение. Огромные файлы (один только `popup.html` весит более 1 МБ, `popup.js` более 560 КБ спагетти-кода на чистом JS).
- **Пригодность для форка:** **Крайне низкая (1/5)**. Попытка форкнуть этот проект для создания легкого `Boosty Chat Overlay` приведет к утопанию в тоннах чужого легаси-кода.

### 5.4. Ghost Chat (`Enubia/ghost-chat`)

## 8. Что обязательно стоит сохранить из нашего проекта

Текущая кодовая база `boosty-chat-overlay` создана под конкретную сложную задачу и содержит решения, которых нет ни в одном стороннем репозитории:

1. **`extension/parser.js`:**
   - Единственный в открытом доступе протестированный парсер живого DOM чата Boosty.
   - Умеет корректно вытягивать цитаты, ответы, аватары из инлайн-стилей и классов CSS-модулей.
   - Детерминированная FNV-1a дедупликация без официального ID сообщения.

2. **Архитектура доставки Extension → Localhost:**
   - Полная независимость от закрытого API Boosty, отсутствие риска бана или утечки токенов пользователя.

3. **Автоматическая настройка сцен OBS (`desktop/main.js`):**
   - Стримеру не нужно копировать URL и вручную добавлять Browser Source в OBS: приложение само находит сцены, создает изолированную служебную сцену `Boosty Chat Overlay` и вкладывает её в рабочую сцену стримера. Это ключевое конкурентное преимущество перед всеми остальными проектами (включая ChallaChat и AxelChat, где стример вынужден вручную вбивать URL в OBS).

4. **Надежный SSE сервер с Last-Event-ID (`server.js`):**
   - Нативное восстановление сообщений при обновлении страницы или перезапуске OBS без дублирования.

5. **Готовая тестовая среда (`test/`):**
   - Набор тестов парсера, серверной устойчивости и headless Electron тестов.

## 9. Оценка трёх вариантов развития (A, B, C)

### Вариант A: Развивать наш текущий проект (Оставить кодовую базу)

- **Суть:** Мы не переключаемся на сторонний репозиторий. Кодовая база остается полностью нашей. Мы постепенно улучшаем архитектуру (миграция на TypeScript, полировка GUI).
- **Плюсы:**
  - Нулевой риск регрессий в работающем Boosty-пайплайне.
  - Кодовая база маленькая (~2.5k строк кода), чистая и полностью понятная для AI/vibe-coding. LLM удерживает весь контекст проекта за один запрос целиком.
  - Нет чужого мертвого кода, ненужных зависимостей (типа Puppeteer или Twitch бота).
- **Минусы:**
  - GUI написан на чистом DOM/Vanilla JS (`desktop/app.js` ~75 КБ) — по мере роста настроек поддерживать Vanilla JS становится медленнее, чем компонентный React/Vue.

### Вариант B: Форк чужого проекта (ChallaChat или StreamHelper)

- **Суть:** Взять ChallaChat или StreamHelper за основу, вырезать их механизмы YouTube/Twitch и встроить наш Boosty parser и OBS интеграцию.
- **Плюсы:**
  - Готовый TypeScript проект с настроенным сборщиком.
- **Минусы:**
  - **Колоссальный объем работы по удалению лишнего:** в ChallaChat придется вырезать тяжелый Puppeteer-слой, систему spoofing браузера; в StreamHelper — вырезать чат-ботов, WinRT интеграции, донатные системы.
  - Риск сломать авто-создание сцен OBS (наше готовое решение уникально).
  - Для AI-моделей работа в чужом репозитории среднего размера (10–15 тыс. строк) часто приводит к галлюцинациям в импортах и незамеченным сайд-эффектам.

### Вариант C: Гибридный путь (Поэтапная модернизация текущего проекта лучшими решениями)

- **Суть:**
  1. **Ядро остается нашим:** `extension/parser.js`, `server.js` (SSE delivery), авто-менеджер OBS-сцен.
  2. **Заимствуем паттерны из ChallaChat:**
     - Модель нормализованного сообщения `ChatEvent` и `Segment[]` (для будущего форматирования эмодзи и ссылок).
     - Архитектуру адаптеров (на случай добавления других площадок в будущем: VK Play Live, Rutube).
  3. **Заимствуем паттерны из StreamHelper:**
     - Модульную организацию `ObsService` на TypeScript.
     - Структуру настроек и компонентный дизайн превью (если стример захочет стилизовать карточки визуально в React).

## 11. Рекомендуемая целевая архитектура

Если стримеру требуется легкое, надежное и быстрое приложение, идеальная целевая архитектура должна выглядеть так:

1. **Runtime:** Electron + Vite (быстрая сборка, мгновенный hot-reload для UI).
2. **Типизация:** Постепенное внедрение TypeScript для разделяемых типов (`shared/types.ts` с моделью `ChatEvent` по образцу ChallaChat/AxelChat).
3. **Boosty Ingestion:** Сохранение нашей связки **Browser Extension + Parser + SSE HTTP Server**. Это самое легкое (0% CPU, <20 МБ RAM) и безопасное для стримера решение на рынке.
4. **OBS Integration:** Сохранение нашего механизма автоматического создания вложенной сцены `Boosty Chat Overlay` через OBS-WS v5.
