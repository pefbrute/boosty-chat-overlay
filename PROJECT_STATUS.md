# Boosty Chat Overlay — текущее состояние и план развития

Актуально на 14 сентября 2026 года.  
Текущая версия приложения: `0.4.0`.

## Коротко о результате

Проект уже является рабочим локальным MVP: настоящее сообщение из Live Chat на Boosty
доходит до прозрачного оверлея и отображается в OBS. Цепочка проверена на Ubuntu с
Brave и OBS Studio 30.2.3.

Стримеру не требуется терминал, Node.js или ручное создание Browser Source. Настольное
приложение запускает сервер самостоятельно, помогает подключить расширение и добавляет
оверлей в явно выбранную сцену OBS.

```text
Boosty Live Chat в браузере
          ↓
расширение Boosty Chat Connector
          ↓
локальный HTTP-сервер 127.0.0.1:17369
          ↓
Server-Sent Events
          ↓
прозрачный HTML-оверлей
          ↓
OBS Browser Source
```

Данные чата не проходят через внешний сервер. Авторизация, cookies Boosty и ключ
трансляции остаются на компьютере стримера.

## Что уже работает

### Получение чата и парсинг

- Расширение работает на страницах `boosty.to` в Chromium-браузерах, включая Brave.
- Разбор DOM вынесен в отдельный модуль `extension/parser.js`, независимый от браузера и покрытый автоматическими тестами.
- Из DOM чата надёжно извлекаются ник, текст сообщения, аватар (через тег или CSS background) и цитаты/ответы.
- **Детерминированный fallback ID**: при отсутствии ID от Boosty вычисляется стабильный FNV-1a хеш на основе `pathname|author|text|publishTime`. Идентичные сообщения в разных стримах не склеиваются, а в рамках одного стрима надёжно дедуплицируются. Если Boosty не предоставляет настоящий message ID, а `publishTime` имеет точность только до минуты, два сообщения одного автора с одинаковым текстом в одной и той же отображаемой минуте могут получить одинаковый fallback ID и быть восприняты как дубль.
- **Rate-limited диагностика**: ошибки разбора сообщений фиксируются в консоли не чаще раза в 5 секунд без утечки персональных данных.
- Новые сообщения отправляются только на локальный адрес приложения.
- Сообщения, уже находившиеся на странице при первом запуске расширения, не выводятся.
- Есть heartbeat, по которому приложение показывает состояние подключения браузера.
- Повторы сообщений дополнительно подавляются локальным сервером.

### Устойчивость доставки и оверлей

- Локальный сервер хранит в памяти кольцевой буфер последних 50 сообщений с уникальными `eventId` и метками `receivedAt`.
- При перезапуске OBS, обновлении страницы оверлея или переключении сцен актуальные сообщения автоматически восстанавливаются.
- Время жизни карточки (TTL) рассчитывается от серверного времени `receivedAt`, поэтому устаревшие сообщения не появляются после перезапуска.
- Автоматический нативный реконнект SSE передаёт `Last-Event-ID`, досылая только пропущенные сообщения без дублирования.
- В оверлее внедрена защита от утечек памяти: хранилище `seenMessageIds` ограничено последними 300 сообщениями.
- Покрыто интеграционными тестами в Chromium/Electron (`npm run test:integration`).
- Статус фикстур: синтетические фикстуры полностью покрывают все форматы сообщений; реальные дампы стрима подключаются через `scripts/capture-boosty-dom.js` (при пустой папке тесты явно информируют `NOT CAPTURED / SKIPPED`).
- Capture snippet сохраняет DOM-структуру и структурно важные атрибуты настолько полно, насколько это возможно при анонимизации. Автоматические тесты проверяют удаление известных пользовательских данных, однако окончательная проверка выполняется после захвата первого реального DOM fixture Boosty. Риск утечки известных типов пользовательских данных существенно снижен автоматической анонимизацией и тестами; полное подтверждение возможно после проверки реального captured fixture.

### Оверлей

- Прозрачная страница подходит для OBS Browser Source.
- Отображаются ник, текст и аватар либо цветная заглушка.
- Есть анимация появления и автоматическое исчезновение сообщений.
- Из GUI настраиваются время показа, число карточек, размер текста, прозрачность фона,
  цвет акцента и отображение аватаров.
- Настройки сохраняются локально и применяются без перезапуска OBS.
- Пользовательский текст вставляется через `textContent`, без выполнения HTML из чата.
- Кнопка тестового сообщения позволяет проверить оверлей без настоящего сообщения Boosty.

### Интеграция с OBS

- Приложение подключается к локальному OBS WebSocket.
- При необходимости включает WebSocket в локальной конфигурации OBS и просит один раз
  перезапустить OBS.
- Из приложения загружается список пользовательских сцен OBS.
- Оверлей создаётся только после явного выбора сцены.
- Создаётся отдельная служебная сцена `Boosty Chat Overlay` с Browser Source
  `Boosty Chat`; в пользовательскую сцену добавляется эта вложенная сцена.
- Выбор запоминается. Если служебную сцену удалили, приложение пытается восстановить её.
- При переносе чата в другую сцену удаляются только принадлежащие приложению элементы
  `Boosty Chat Overlay` и `Boosty Chat`. Остальные источники и настройки OBS не меняются.
- Оверлей не добавляется сразу во все сцены.

### Настольное приложение и сборки

- Есть Electron GUI без необходимости пользоваться терминалом.
- Приложение умеет открыть Boosty, предпросмотр и страницу управления расширениями
  выбранного установленного браузера.
- В Linux приложение зарегистрировано в системе и запускается через обычную иконку.
- Собирается автономный Linux AppImage.
- Кроссплатформенно собран Windows portable EXE.
- Подготовлен ZIP расширения для последующей публикации.

## Что проверено на практике

- Настоящее сообщение из тестовой трансляции Boosty появилось на странице оверлея.
- То же сообщение появилось в превью OBS.
- Изменение настроек внешнего вида применяется к оверлею.
- OBS Browser Source и служебная сцена создаются автоматически.
- Удалённая служебная сцена восстанавливается приложением.
- AppImage запускается на тестовой Ubuntu.
- Выбор браузера и ручная загрузка распакованного расширения работают с Brave.

## Что пока нельзя считать полностью проверенным

- Windows-сборка создана, но полный пользовательский тест на настоящей Windows ещё не
  проведён.
- macOS-сборка указана в конфигурации, но не собрана и не проверена. Подписывания и
  notarization нет.
- Firefox-вариант расширения не опубликован и не прошёл полноценный end-to-end тест.
- Не проведены длительные многочасовые эфиры с большим потоком сообщений.
- Не проверены все варианты emoji, стикеров, ответов, упоминаний, ссылок, удалённых
  сообщений и модераторских действий.
- События подписок, платежей и донатов пока не реализованы.
- Поведение при изменении Boosty DOM гарантировать нельзя: селекторы придётся обновить,
  если Boosty изменит разметку чата.
- Не проверены старые версии OBS и нестандартные конфигурации OBS WebSocket.

## Главные ограничения текущей версии

### Установка расширения всё ещё ручная

Браузеры не разрешают стороннему приложению незаметно установить непроверенное
расширение. Сейчас приложение открывает нужный браузер и папку, но пользователь должен
включить режим разработчика и выбрать «Загрузить распакованное».

Нормальное массовое решение — публикация в Chrome Web Store и Firefox Add-ons. Тогда
в интерфейсе будут обычные кнопки «Установить», ведущие на официальную страницу магазина.

### Поддержка Boosty зависит от текущей разметки сайта

Коннектор читает элементы с `data-test-id` в DOM Boosty. Это практичнее и безопаснее,
чем извлекать cookies или неофициальные токены, но при редизайне Boosty расширение может
потребовать обновления.

### Приложение ещё не является подписанным массовым релизом

Windows SmartScreen и macOS Gatekeeper могут предупреждать о неизвестном издателе.
Для беспроблемной установки понадобятся сертификаты подписи, стабильный установщик и
автоматические обновления.

## Приоритетный roadmap

### P0 — довести до версии, которую безопасно отдавать стримерам

1. Провести чистый end-to-end тест Windows: установка, Brave/Chrome, Boosty, OBS,
   перезапуск и удаление/восстановление сцены.
2. Добавить автоматические тесты безопасной работы со сценами OBS: выбранная сцена,
   перенос, удалённая сцена, переименование и отсутствие OBS.
3. Обработать переименование или удаление выбранной пользовательской сцены понятным
   сообщением без создания источников в случайном месте.
4. Проверить, что приложение никогда не удаляет одноимённый пользовательский источник,
   созданный не им. В перспективе хранить UUID/идентификаторы созданных элементов, а не
   ориентироваться только на имена.
5. Обновить README и встроенную справку под окончательный сценарий установки.

### P1 — убрать оставшуюся мозгоёблю при установке

1. Опубликовать расширение в Chrome Web Store.
2. Подготовить и проверить отдельную версию для Firefox Add-ons.
3. Сделать нормальный Windows Setup в Windows CI, а не только portable EXE.
4. Подписать Windows и macOS сборки.
5. Добавить автоматическое обновление приложения и понятное уведомление о новой версии.
6. Сделать мастер первого запуска: браузер → Boosty → выбор сцены OBS → тестовое сообщение.

### P2 — надёжность реального эфира

1. Провести нагрузочный и многочасовой тест.
2. Добавить автоматическое переподключение и понятную диагностику каждого звена.
3. Хранить небольшой локальный журнал ошибок без паролей, cookies и текста приватных
   сообщений; добавить кнопку «Скопировать отчёт для поддержки».
4. Защитить локальные endpoints одноразовым ключом между расширением и приложением.
5. Ужесточить CORS вместо текущего разрешения `Access-Control-Allow-Origin: *`.
6. Добавить версионирование протокола между приложением и расширением.

### P3 — функции для стримеров

1. Готовые темы оформления и визуальный редактор карточки.
2. Позиционирование и безопасные зоны прямо из приложения.
3. Выделение автора канала, модераторов, подписчиков и платных сообщений.
4. Фильтр ссылок, стоп-слова, скрытие пользователей и антиспам.
5. TTS с очередью, лимитами и фильтрацией.
6. События подписок и платежей, если удастся надёжно получить их без передачи
   авторизационных данных внешнему серверу.
7. Объединение Boosty с YouTube, Twitch, VK и другими чатами — отдельный большой этап,
   а не обязательная часть первого стабильного релиза.

## Технический долг

- Версии в `package.json`, `package-lock.json` и manifest расширения сейчас расходятся;
  перед публичным релизом нужен единый процесс версионирования.
- Исторические разделы `SESSION_REPORT.md` описывают ранние версии и не должны
  восприниматься как инструкция для актуальной сборки.
- Нужны unit/integration tests и CI для Linux/Windows/macOS.
- Нужна миграция настроек между версиями и обработка повреждённого конфигурационного файла.
- Стоит разделить большой OBS workflow на небольшие тестируемые функции.
- Нужны лицензия проекта, политика приватности расширения и сведения об авторе/издателе.

## Критерий готовности первого публичного релиза

Версию можно считать готовой для публичной раздачи, когда новый пользователь на чистой
Windows без терминала сможет:

1. Установить подписанное приложение обычным установщиком.
2. Установить расширение из официального магазина одним нажатием.
3. Открыть Boosty и выбрать сцену OBS.
4. Увидеть успешное тестовое сообщение.
5. Перезапустить браузер, OBS и приложение без повторной ручной настройки.
6. Получить понятное сообщение и инструкцию, если любой из этапов не работает.

До этого состояния техническая основа уже доведена; основной объём оставшейся работы —
упаковка, проверка на разных системах, защита от редких сценариев и публикация расширения.
