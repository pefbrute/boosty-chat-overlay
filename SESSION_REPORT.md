# Boosty Chat Overlay — журнал первой рабочей сессии

Дата: 28 августа 2026 года  
Система: Ubuntu 22.04.5 LTS, Linux 6.8, Europe/Moscow  
Рабочая папка проекта: `/home/fedor/projects/boosty-chat-overlay`

## С чего всё началось

Задача возникла из разговора о том, что стримеру нужен вывод чата Boosty прямо на экран
трансляции в OBS. Изначально рассматривались два варианта:

1. Найти готовое решение.
2. Если готовое решение не работает — сделать собственный локальный коннектор
   `Boosty → OBS`.

Готовым кандидатом был AxelChat. Он официально заявляет поддержку Boosty, умеет
создавать веб-виджеты для OBS и объединять чаты разных платформ. Идея первоначального
теста была следующей:

```text
Boosty → AxelChat → Web widget → OBS Browser Source
```

Поскольку тестовый компьютер работает на Ubuntu, AxelChat предполагалось запускать
через Wine. Сам AxelChat является Windows-приложением.

Это изолировало AxelChat от других Windows-приложений и от стандартного Wine-профиля.
Однако встроенная авторизация всё равно завершилась падением `CefWebEngine.exe`.

Основная ошибка Wine:


нецелесообразным.

На настоящей Windows AxelChat всё ещё может быть готовым решением для стримера, но
полностью проверить цепочку на текущем Ubuntu-компьютере через AxelChat не удалось.

## Переход к собственному решению

Было решено создать нативный локальный прототип без Wine:

```text
Boosty в обычном Chrome/Brave
        ↓
локальное расширение браузера
        ↓
HTTP POST на 127.0.0.1
        ↓
локальный Node.js-сервер
        ↓
Server-Sent Events
        ↓
прозрачный веб-оверлей
        ↓
OBS Browser Source
```

Ключевой принцип безопасности: расширение читает только уже открытую и авторизованную
страницу Boosty. Пароль, cookies и ключ трансляции не передаются нашему серверу или
какому-либо внешнему сервису. Локальный сервер слушает только:

```text
127.0.0.1:17369
```

## Что делает локальный сервер

`server.js` запускает HTTP-сервер на `127.0.0.1:17369` и предоставляет:

- `/overlay/` — прозрачную страницу чата для браузера и OBS;
- `/events` — поток Server-Sent Events для новых сообщений;
- `/message` — локальный POST endpoint для расширения;
- `/test` — генерацию тестового сообщения.

Сервер запускается командой:

```bash
cd /home/fedor/projects/boosty-chat-overlay
npm start
```

Во время сессии сервер был успешно запущен и проверен. Страница оверлея отдалась по
HTTP, а `/test` вернул:

```json
{"ok":true}
```

## Создание тестовой трансляции Boosty

На странице автора Boosty была открыта форма `New stream`. Для теста:

- заголовок установлен как `Тест чата`;
- выбран один из уровней подписки, поскольку Boosty требует уровень доступа;
- чат оставлен включённым;
- сохранение записи оставлено выключенным;
- обложка, описание и DonationAlerts не использовались;
- OBS на этом этапе не запускал видеопоток.

После создания открылась реальная страница трансляции со статусом:

```text
Stream Starting Soon
```

Справа был доступен `Live chat` и поле `Send message`. Таким образом, для проверки DOM
чата не потребовалось передавать в Boosty видеосигнал.

## Исследование DOM реального Boosty-чата

Первая версия расширения только наблюдала за добавляемыми элементами и выводила
кандидатов в консоль браузера. В чат было отправлено сообщение:

```text
тест 123
```

В DevTools были обнаружены стабильные атрибуты Boosty:

```text
data-test-id="CHATMESSAGE:root"
data-test-id="CHATMESSAGE:author"
data-test-id="CHATMESSAGE:message"
```

Также внутри корня сообщения присутствовал элемент аватара с классом, содержащим
`Avatar`.

После этого `extension/content.js` был обновлён. Текущая версия:

1. Следит за изменениями страницы через `MutationObserver`.
2. Находит новые элементы `[data-test-id="CHATMESSAGE:root"]`.
3. Извлекает автора из `CHATMESSAGE:author`.
4. Извлекает текст из `CHATMESSAGE:message`.
5. Пытается получить аватар из `img` или CSS `background-image`.
6. Отправляет объект сообщения на локальный endpoint `/message`.
7. Помечает обработанные DOM-узлы через `WeakSet`, чтобы не отправлять один и тот же
   элемент повторно в рамках текущей страницы.

После изменения расширение было перезагружено на `chrome://extensions/`, а страница
Boosty обновлена.

## Текущий внешний вид и поведение

Оверлей уже поддерживает:

- прозрачный фон страницы;
- карточки сообщений на тёмном полупрозрачном фоне;
- оранжевый акцент Boosty;
- ник автора;
- текст сообщения;
- аватар или цветную заглушку;
- анимацию появления;
- максимум шесть видимых сообщений;
- автоматическое удаление карточки через 20 секунд;
- безопасный вывод текста через `textContent`, без вставки произвольного HTML.

## Ограничения текущего прототипа

Это рабочий MVP, но ещё не готовый установочный продукт:

1. Локальный сервер пока запускается вручную через `npm start`.
2. Расширение загружается вручную в режиме разработчика.
3. Нет графического окна настроек.
4. Время исчезновения и оформление пока задаются в коде.
5. Защита от повторов действует на DOM-узлы текущей страницы; после полной перезагрузки
   Boosty старые видимые сообщения могут быть отправлены заново.
6. Селекторы основаны на актуальных `data-test-id` Boosty. Если Boosty полностью изменит
   DOM чата, коннектор потребуется обновить.
7. Не проверены длинные сообщения, все виды emoji, ответы, удаление сообщений,
   модераторские события, донаты и подписки.
8. Не подготовлена Windows-сборка для передачи другому стримеру.
9. Сервер принимает локальные сообщения без токена. Он слушает только loopback, но перед
   распространением приложения можно добавить одноразовый локальный ключ.

## Безопасность и приватность

- Пароль Boosty вводится только на официальном сайте Boosty в обычном браузере.
- Расширение не читает и не экспортирует cookies.
- Stream key не записан в проект и не приведён в этом отчёте.
- Локальный сервер привязан к `127.0.0.1`, а не ко всем сетевым интерфейсам.
- Сообщения не отправляются во внешний облачный сервис.
- В оверлее пользовательский текст вставляется через `textContent`, что снижает риск
  HTML/script-инъекций.

## Итог сессии

Начали с проверки готового AxelChat. Он запускался через Wine, но его встроенный
CEF-браузер стабильно падал при авторизации Boosty. После нескольких диагностических
попыток от Wine-варианта отказались и создали собственный локальный прототип.

К концу сессии собственный прототип успешно передал настоящее сообщение из Boosty
через браузерное расширение и локальный сервер в прозрачный оверлей, а затем вывел его
в OBS. Основная техническая гипотеза подтверждена: нативный локальный
`Boosty → OBS Chat Overlay` реализуем и уже работает в минимальном виде.

## Продолжение: переход от прототипа к приложению 0.2.0

После успешного MVP было сформулировано продуктовое требование: стример не должен
использовать терминал, знать Node.js, порты или вручную настраивать технические файлы.
Проект переведён на Electron и получил обычное графическое окно.

Версия 0.2.0:

- самостоятельно запускает локальный сервер вместе с приложением;
- показывает состояние приложения, браузерного коннектора и оверлея;
- считает полученные сообщения;
- открывает Boosty и предпросмотр кнопками;
- подключается к локальному OBS WebSocket;
- автоматически создаёт или обновляет Browser Source `Boosty Chat` в текущей сцене;
- локально читает уже созданный OBS пароль, не показывает его и не сохраняет в проекте;
- при выключенном OBS WebSocket включает его в конфигурации и просит один раз
  перезапустить OBS;
- подавляет повторные сообщения на сервере в течение десяти минут;
- не отправляет уже видимые старые сообщения при первой загрузке страницы Boosty;
- получает heartbeat от расширения каждые пять секунд.

Автоподключение было проверено на OBS 30.2.3. В сцене `Тест бусти` успешно создан
источник `Boosty Chat` с URL локального оверлея. Эфир и запись не запускались.

Собраны артефакты:

```text
dist/Boosty Chat Overlay-0.2.0.AppImage
dist/Boosty Chat Overlay 0.2.0.exe
dist/extensions/boosty-chat-connector-0.2.0.zip
```

AppImage автономно запущен и его встроенный `/health` успешно проверен. Windows
portable EXE успешно собран кроссплатформенно на Linux. Полноценный NSIS Setup при
кросс-сборке не создал служебный uninstaller; его следует собирать в Windows CI.

Остающееся неизбежное ограничение браузеров: сторонняя программа не имеет права тихо
установить расширение. Для пользовательского сценария «один клик» расширение нужно
опубликовать в Chrome Web Store и Firefox Add-ons. ZIP для публикации уже подготовлен.

- Выбранная сцена запоминается, чтобы автоматически восстановить оверлей после удаления или перезапуска OBS.
- При переносе в другую сцену приложение удаляет из прежних сцен только собственные элементы `Boosty Chat Overlay` / `Boosty Chat`. Остальные сцены, источники и настройки OBS не изменяются.

## Улучшение устойчивости и изолированный парсер (Сентябрь 2026)

Реализован комплекс мер по повышению отказоустойчивости цепочки доставки сообщений и защите расширения от изменений в верстке Boosty:

1. **История и восстановление сообщений (Message Recovery)**:
   - В памяти локального сервера (`server.js`) развернут буфер последних 50 сообщений с инкрементальными уникальными `eventId` и точными метками времени `receivedAt`.
   - При открытии нового оверлея (или обновлении Browser Source в OBS) клиенту автоматически передаются актуальные последние сообщения.
   - В оверлее внедрен точный расчет оставшегося TTL карточки на базе серверного `receivedAt`: сообщения, чей срок жизни уже истек, не отображаются повторно, а активные показываются ровно на оставшееся время.
   - Реализована поддержка заголовка `Last-Event-ID`: при нативном переподключении SSE сервер досылает только пропущенные сообщения.
   - Защита от дублей: в `overlay.js` добавлен циклический буфер `seenMessageIds` (ограничен 300 последними сообщениями для исключения утечек памяти при многочасовом эфире).

2. **Модульный парсер сообщений Boosty (`extension/parser.js`)**:
   - Логика извлечения данных из DOM выделена в чистый UMD-модуль, работающий как в контентном скрипте расширения (`globalThis.BoostyParser`), так и в Node.js без браузера.
   - Приоритетная система селекторов корректно изолирует блоки заголовка, автора, текста, вложенных эмодзи и цитат/ответов.
   - Поддерживаются аватары как в виде `<img>` тегов, так и через CSS background-image.

3. **HTML-фикстуры и автоматические тесты**:
   - В `test/fixtures/` созданы 6 эталонных HTML-образцов сообщений Boosty: обычный текст, аватар через тег, аватар через background, сообщение с эмодзи, длинный текст, цитирование/ответ (reply).
   - Написан тестовый набор `test/parser.test.js` с использованием встроенного `node:test` и легковесного `linkedom`.
   - Серверные тесты расширены сценариями переподключения, фильтрации по `Last-Event-ID`, дедупликации и лимита в 50 сообщений (`scripts/test-server.js`).
   - Написан сквозной проверочный скрипт `scripts/verify-resilience.js`. Все тесты пройдены на 100%.

4. **Финальное усиление устойчивости и интеграционная верификация в Chromium**:
   - **Детерминированный fallback ID**:
     - В `extension/parser.js` исключена генерация невоспроизводимых идентификаторов через `Date.now()` и `Math.random()`.
     - При отсутствии явного идентификатора от Boosty вычисляется детерминированный отпечаток `pathname|author|text|publishTime` через 32-битный FNV-1a хеш (`fallback-xxxxxxxx`).
     - Гарантировано: одно и то же сообщение в рамках одной страницы получает идентичный ID и дедуплицируется; одно и то же сообщение в разных чатах/каналах (разные `pathname`) получает разные ID.
     - Допустимое остаточное ограничение: если Boosty не предоставляет настоящий message ID, а `publishTime` имеет точность только до минуты, два сообщения одного автора с одинаковым текстом в одной и той же отображаемой минуте могут получить одинаковый fallback ID и быть восприняты как дубль.
   - **Диагностика ошибок парсинга**:
     - Внедрено rate-limited предупреждение в консоль (`[Boosty Parser] Failed to parse message (...)`), срабатывающее не чаще раза в 5 секунд при нарушении целостности корневых элементов чата без спама и без вывода персональных данных.
   - **Разделение тестов и честный статус фикстур**:
     - Быстрые юнит- и функциональные тесты вынесены в `npm test` (проверка синтаксиса `npm run check`, серверные тесты `test-server.js`, синтетические фикстуры `parser.test.js`, восстановление `verify-resilience.js`).
     - Папка `test/fixtures/real/` оставлена пустой, искусственные данные туда не генерировались.
     - При отсутствии сохраненных дампов реального стрима тесты честно и заметно выводят баннер:
       `⚠ Real Boosty fixtures: NOT CAPTURED / SKIPPED`.
     - Создан готовый сниппет DevTools `scripts/capture-boosty-dom.js` для копирования анонимизированного outerHTML через `copy()`.
     - Сниппет рекурсивно обходит текстовые узлы (`anonymizeTextNodes`), гарантируя удаление пользовательского текста даже при глубокой вложенности (`span`, `strong`, `em`) без разрушения тегов и атрибутов `alt` у emoji.
     - Capture snippet сохраняет DOM-структуру и структурно важные атрибуты настолько полно, насколько это возможно при анонимизации.
