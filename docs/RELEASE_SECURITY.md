# Release Security, Antivirus QA & Reputation Gate

Этот документ регламентирует политику доверия, проверку безопасности, антивирусный аудит и процедуры валидации Windows-сборок Boosty Chat Overlay перед релизом.

Цель — сделать происхождение каждого бинарника прозрачным, исключить попадание вредоносного кода или случайных утечек секретов, свести к минимуму риск ложных срабатываний (False Positive) и предоставить стримерам проверяемые доказательства безопасности.

---

- [x] **Secret Scan Clean:** `gitleaks` проверил всю историю коммитов и рабочую директорию. Секретов не обнаружено.

## 2. Release Blockers (Критерии блокировки релиза)

Релиз **КАТЕГОРИЧЕСКИ БЛОКИРУЕТСЯ**, если:
1. Microsoft Defender или ClamAV выдают детекты вредоносного ПО (Trojan, Backdoor, Ransom, Downloader, PUA).
2. Обнаружен реальный приватный ключ, пароль, токен или секрет в репозитории или пакете.
3. В production-установщик попали посторонние бинарники, тестовые артефакты или node_modules сборочных инструментов (Remotion, Playwright).
4. SHA-256 опубликованного установщика не совпадает с SHA-256 проверенного артефакта.
5. Неизвестно происхождение сборки (отсутствует привязка к Git commit).
6. 3+ антивирусных движка на VirusTotal или хотя бы один крупный вендор (Microsoft, Kaspersky, ESET, Bitdefender, Sophos) дают детект вредоносного ПО.

## 3. Архитектура доверия (Local-First Trust)

Boosty Chat Overlay спроектирован по принципу максимальной прозрачности:
- **Никаких скрытых шеллов:** Код не вызывает скрытые `cmd.exe` или PowerShell-скрипты на пользовательской машине. Единственные запуски внешних процессов происходят строго по нажатию кнопок пользователем:
  - `launchObs`: запуск исполняемого файла `obs64.exe` при клике «Запустить OBS»;
  - `openPreferredBrowser`: открытие страницы `chrome://extensions` / `brave://extensions` / `browser://tune` при клике «Открыть расширения».
- **Локальный транспорт:** Сервер слушает только локальный адрес `127.0.0.1:17369`. OBS WebSocket подключается к `127.0.0.1:4455`. Содержимое чата стримера передаётся напрямую из браузера на локальный HTTP/WebSocket сервер.
- **Отсутствие телеметрии:** Приложение не собирает аналитику, не логирует личные данные и не отправляет пользовательские данные на сторонние серверы. Единственный внешний запрос — проверка свежей версии через публичный `api.github.com`.

## 4. Исследование вариантов Code Signing для Windows (2026)

Для устранения предупреждения Windows SmartScreen («Система Windows защитила ваш компьютер / Неизвестный издатель») требуется цифровая подпись Authenticode.

С 1 июня 2023 года требования CA/Browser Forum запрещают хранить приватные ключи сертификатов подписи кода в обычных файлах (`.pfx`) на диске. Все ключи обязаны храниться либо на сертифицированном физическом аппаратном токене (FIPS 140-2 Level 2 / Common Criteria EAL 4+), либо в облачном сервисе HSM.

### Сравнительный анализ вариантов:

| Опция | Стоимость | Требования к верификации | Плюсы | Минусы | Подходит ли нам? |
|---|---|---|---|---|---|
| **Microsoft Azure Trusted Signing** *(ранее Microsoft Artifact Signing)* | **~$10 / месяц** (активный пул) | Верификация физлица или юрлица через партнёра Microsoft (Identity Verification) | • Родная интеграция с Windows и SmartScreen<br>• Прямое доверие Microsoft Root CA<br>• Работает в GitHub Actions без физических токенов<br>• Самая низкая стоимость в индустрии | • Требует аккаунт Microsoft Azure и разовую валидацию личности | **РЕКОМЕНДУЕТСЯ** (Оптимальный выбор для независимого разработчика) |
| **Стандартный OV Code Signing** (Sectigo, DigiCert, Certum) | **$300 – $500 / год** + $80-$120 за доставку токена | Документы, паспорт, подтверждение адреса, телефонный звонок | • Стандартный X.509 сертификат | • Дорогая доставка физического USB-ключа<br>• Сложно автоматизировать в CI/CD<br>• SmartScreen всё равно требует времени для набора репутации | Нет (неудобно для CI, дорого) |
| **EV Code Signing** (DigiCert, GlobalSign) | **$600 – $1000+ / год** | Полная корпоративная верификация (юрлицо, выписка ЕГРЮЛ, звонок) | • Мгновенная репутация SmartScreen с первого дня | • Недоступно физическим лицам без юрлица<br>• Очень высокая цена | Нет |
| **Текущий Unsigned Release** | **$0** | Никаких | • Бесплатно<br>• Полный open-source и воспроизводимость | • SmartScreen показывает синий экран неизвестного издателя при первом запуске («Подробнее» → «Выполнить в любом случае») | **Текущий базовый статус** |

### Рекомендация для Boosty Chat Overlay:
**Azure Trusted Signing**:
Когда проект будет готов к покупке подписи, оптимальным выбором является Azure Trusted Signing. Он поддерживается в GitHub Actions через официальный `azure/trusted-signing-action`, подписывает бинарники в облаке Azure HSM за секунды и быстро получает репутацию у защитных механизмов Windows.

## 5. Порядок и процедура подписи (Sign Order Pipeline)

Если в проект добавляется сертификат:
1. `build` — компиляция и сборка бинарников.
2. `sign application` — подпись `Boosty Chat Overlay.exe` и вспомогательных исполняемых файлов (`elevate.exe`).
3. `package` — упаковка установщика NSIS через `electron-builder`.
4. `sign installer` — подпись полученного `Boosty Chat Overlay Setup X.Y.Z.exe`.
5. `verify signature` — проверка валидности цепочки и обязательного RFC 3161 timestamp (`Get-AuthenticodeSignature` / `osslsigncode verify`).
6. `checksum` — подсчёт итоговых SHA-256.
7. `publish` — публикация релиза.

*Правило:* Никогда не модифицировать файлы после наложения подписи, так как любое изменение байтов аннулирует цифровую подпись.

## 6. SmartScreen vs Malware: Разделение понятий

Критически важно различать два совершенно разных события:

| Событие | Что пишет Windows | Причина | Что это значит |
|---|---|---|---|
| **Malware Detection** | «Обнаружена угроза: Trojan:...», антивирус блокирует или удаляет файл | Сигнатура в базе антивируса или вредоносная эвристика | **Блокер релиза.** Файл считается вредоносным. Требуется немедленный разбор. |
| **SmartScreen Reputation Warning** | «Система Windows защитила ваш компьютер. Неизвестное приложение» | Файл не имеет сертификата Authenticode и/или ещё не набрал достаточного количества скачиваний в мире | **Штатное поведение для новых/unsigned приложений.** Не означает вирус. |

## 7. Регламент действий при False Positive (Ложном срабатывании)

Если какой-либо антивирус среагировал на чистый бинарник:
1. **Категорический запрет на сокрытие:** Запрещено обфусцировать код, применять крипторы или менять сборочный мусор ради «обхода».
2. **Фиксация точных данных:** Записать точное имя детекта, версию базы антивируса и SHA-256 бинарника.
3. **Отправка официального False Positive Submission:**
   - **Microsoft Defender:** [Microsoft Security Intelligence Submission](https://www.microsoft.com/en-us/wdsi/filesubmission) (раздел *Software developer*).
     - Приложить ссылку на GitHub-репозиторий;
     - Указать, что проект является открытым ПО;
     - Получить Submission ID и отслеживать статус снятия детекта (обычно 2–24 часа).
   - **Другие вендоры:** Официальные порталы отправки ложных срабатываний (Kaspersky Whitelist, ESET Sample Submission, VirusTotal False Positive Notification).
4. **Фиксация результата:** После переклассификации обновить базу антивируса и подтвердить чистый статус.
