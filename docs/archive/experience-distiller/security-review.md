# Аудит безопасности и контроль доступа: Experience Distiller v2.2

## 1. Модель угроз (Threat Model)

Транскрипты сессий (`~/.gemini/antigravity/brain/`) и логи инструментов содержат недоверенный пользовательский и внешний контент (выводы curl, git, npm, ошибки сборки, сторонние репозитории).

Основные векторы атак:
1. **Prompt Injection в логах**: попытки заставить LLM-анализатор игнорировать инструкции (`"ignore previous instructions"`, `<system>`).
2. **Утечка секретов и токенов**: наличие ключей API, токенов авторизации или паролей в вызовах команд.
3. **Несанкционированное изменение файлов**: попытки кода улучшений напрямую перезаписать критические файлы проекта (`main.js`, `package.json`) без участия пользователя.
4. **Выход за пределы каталога (Path Traversal)**: манипуляции с путями `target_path: ../../.bashrc`.

---

## 2. Реализованные механизмы защиты

### 2.1. Обезвреживание Prompt Injection
В `src/security.py` все входящие фрагменты запросов и логов экранируются регулярными выражениями:
- `ignore previous instructions` $\to$ `[DEFANGED_INJECTION_IGNORE_INSTRUCTIONS]`;
- `<system>` $\to$ `[DEFANGED_TAG_SYSTEM]`;
- `you are now unrestricted` $\to$ `[DEFANGED_INJECTION_PERSONA]`.

### 2.2. Маскирование секретов
Все токены GitHub (`ghp_*`), JWT, пароли (`--password ...`) маскируются на этапе чтения до попадания в `llm_packet.json`:
- `[REDACTED_PASSWORD]`;
- `[REDACTED_GITHUB_TOKEN]`;
- `[REDACTED_JWT]`.

### 2.3. Изоляция рабочего пространства (Staging Boundary)
- Builder создает временный изолированный каталог `/tmp/distiller-stage-<id>-*`.
- Ни один файл в целевом проекте пользователя не изменяется в процессе `experience-distiller improve`.
- Все изменения формируются исключительно в виде unified diff `.patch`.
- Применение патча требует явного флага `--apply` и подтверждения пользователя.

### 2.4. Безопасность Validation Gate
Перед формированием патча каждый файл в staging проходит автоматическое сканирование `scan_for_secrets()`. При обнаружении любого несмягченного токена вердикт немедленно переводится в `failed`.
